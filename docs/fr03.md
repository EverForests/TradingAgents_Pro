## Report-ready section: FR-03 sentiment evidence coverage

### Problem and requirement

The inherited sentiment analyst combines news, StockTwits and Reddit. In the preserved upstream revision, the schema offered measured sentiment bands and a numeric score but could not represent UNKNOWN with a null score. A controlled real-school diagnostic for AAPL on 2026-11-10 returned Neutral/5.0/low although no substantive source was available. That diagnostic included an additional instruction limiting narrative length; it is evidence of an observed failure, not a fully matched system-level experiment. A separate offline probe showed that the real original node, renderer and bull-research prompt accepted an explicitly injected Neutral/5.0 response when sources were missing. Neither observation means the schema mathematically forces a score of five.

FR-03 separates evidence coverage from sentiment direction. Zero valid sources must produce NO_DATA, UNKNOWN and a null score without invoking the sentiment model. One or two valid sources produce PARTIAL_DATA, and three produce AVAILABLE. A valid measured Neutral/5.0 remains legal. A failed assessment retains its actual source coverage while returning UNKNOWN/null, and missing sentiment must not prevent other usable analysis from continuing.

### Design and engineering contribution

We chose local deterministic components at the existing collection and analyst boundaries. Prompt-only instructions could request caution but could not enforce missingness, and replacing the orchestration would create unnecessary integration work. The three logical sources remain news, StockTwits and Reddit; multiple Reddit communities count once. Each opt-in collector returns a string-compatible SourceText with an immutable request-bound receipt. Receipts identify the vendor, requested ticker/window and item metadata without copying raw post bodies into evidence identifiers. Legacy callers retain their default return formats and vendor routes.

The program, rather than the model, validates dates, instrument attribution, substantive content and collection failures. The inherited window is seven days back through the analysis day: for 2026-11-10, UTC 2026-11-03 00:00 is included and 2026-11-11 00:00 is excluded. Existing canonical-symbol rules reconcile supported ticker aliases. Run identities remain exact, and every fresh run receives a new identity. The model can assess admitted observations but cannot create additional source coverage. One authoritative assessment renders the legacy report and AIMessage, preserving consumer compatibility. Optional-source failure, assessment failure and final publication authority are kept separate; C1/C4 integration belongs to their respective owners.

### Supervised development record and interventions

Application and executable test changes were produced through actual OpenCode 2.3.0 sessions with the school model. Automation tools coordinated the work under the student's broad autonomous delegation, reviewed plans and generated artifacts, ran checks and performed documented formatting and maintainer operations. Individual student approval of each concrete plan or test did not occur and is not reconstructed as a historical event. Native session exports, per-run JSONL and operator requests are retained privately with annotations identifying the actual actor.

The process used independent positive and negative fixtures before source changes. The original zero-source test invoked its fake model once where zero was expected. Subsequent checks exposed an import-cycle mistake, interface drift and vendor-specific metadata assumptions, which were corrected without discarding the original failure records. A school compatibility failure revealed unsupported json_schema responses; the sentiment binding adopted function_calling. A partial-coverage test criterion was corrected before the final historical r3 run to match C3's explicit allowance for UNKNOWN when assessment fails. Earlier failed runs were not relabeled as passing. The neutral prompt was also repaired because silence was incorrectly stated as the condition for Neutral.

Later maintenance found contradictory blank bodies with valid-looking metadata, malformed receipt/outcome containers, inconsistent counts/references, blank identities and oversized integer scores. Forty new checks initially had 27 failures; two additional extreme scores raised OverflowError. After repair, the frozen 42 checks passed. Independent review was assessed against code rather than accepted automatically: removing the body guard would have restored the demonstrated defect. A narrower real false-negative was reproduced for genuine No-found headlines, alongside node-approved lowercase/canonical ticker inputs. All five added positive cases failed before the second repair and passed afterward. Existing 42 expectations were unchanged.

### Evaluation and limits

The final application revision b2816ec passed 47 boundary checks and a combined offline suite of 1533 tests plus 100 subtests. Thirty-nine checks were skipped: six existing platform/optional-dependency cases and 33 paired checks without a configured reference checkout. The paired suite was separately configured and passed all 33 assertions across 16 matched synthetic cases on the original and final nodes. With the same fixed fake Neutral/5.0 model answer, unsupported measurements fell from five to zero, all eleven valid-source controls preserved Neutral/5.0, and fake sentiment invocations fell from sixteen to eleven. Both workers verified import roots and revisions; no network attempt occurred. This demonstrates deterministic missing-data behavior, not a natural-model error rate or financial performance.

The latest real-school synthetic controls were run at 06d160a: three cases passed with two actual HTTP attempts; zero sources sent none, while one and three sources measured Neutral/5.0. Thinking was disabled, streaming enabled and the output allowance was 4096. That evidence remains attributed to its recorded revision. Later deterministic repairs did not change prompts or the client and did not trigger additional runtime requests. Real-provider quality, semantic accuracy on independently labeled market data, investment returns and combined C1/C4 acceptance remain unverified. The contribution is an enforceable evidence boundary, reproducible verification and an honest process record; it is not a claim of improved trading returns.

Student's broad instruction: autonomous continuation. Per-item student approval, individual authorship of the generated code, formal human approval and team contribution weights: not recorded or inferred.
