# Project report

## NFR-01 — Per-run model request budget (owner: JunKai Yan)

> Draft supplied by the requirement owner for the team report. Figures are the recorded local results on base `3d5ce62`, with the earlier `486a9a5` numbers kept only as history in the review memo; the team coordinator may trim, but should not restate them as end-to-end acceptance, which still depends on integrator wiring.

**Requirement.** NFR-01 bounds the number of *actual* model requests in one stock-analysis run by a configurable positive integer. It is a property of the outbound boundary, not of any analyst's internal loop, so per-node configuration cannot satisfy it. INV-02 tightens the statement for concurrency: the limit must hold even when two dispatch paths race for the last slot, and the refusal must never be replaced by a fabricated decision.

**Design.** The deliverable is one owner module, `tradingagents/llm_clients/request_budget.py`, implementing contract C4. A `RequestBudget` is bound to a `run_id` and a limit; `try_reserve()` atomically takes a slot or returns `None`; `charge_attempt()` moves a reservation to a charged attempt at the outbound boundary; `cancel_before_send()` releases a slot only when the transport is known not to have started; `snapshot()` exposes charged attempts, known sends, unknown-delivery attempts, active reservations and exhaustion. `dispatch(prepared, budget, send)` requires a READY prepared request, reserves, charges, sends exactly once and raises a typed failure — `BudgetExhausted`, `ContextTooLarge` or `ProviderFailure` — instead of returning a placeholder recommendation. An ambiguous provider error keeps the slot charged and the attempt counted as unknown delivery, which is what makes the counter reflect reality rather than intent. There is deliberately no unmetered mode and no reset API: a restarted analysis is a new run with a new identity.

**Verification.** The offline suite holds 39 tests across the frozen case IDs T-NFR01-BOUNDARY, RETRY, ISOLATION, FAILURE, RESUME and T-INV02-RACE, using an inline thread-safe fake transport that counts real sends. The pre-implementation baseline on this tree was 37 failed and 1 passed, the single pass being a static source guard that must hold on both sides. After implementation the suite is 39 passed, the full repository regression is 1412 passed with one unrelated skip, and `ruff check` on both files is clean. Because a passing suite can still be blind, four mutation experiments removed enforcement outside the repository: disabling the capacity guard turned 13 tests red, removing the cancellation release turned 2 red, removing delivery confirmation turned 5 red, and removing the reservation lock turned 2 red. The last of these was added because the original race cases contended through the low-level primitives rather than through `dispatch`, a coverage gap the planning role found on the second pass; the appended test now races two threads through `dispatch` for the last slot, and the delivery-confirmation mutation is what proves it can fail. The independent verify role returned "conditionally compliant" and refused to sign off any claim that the requirement is already enforced, which is the correct reading: the module meets its contract, the application does not yet call it.

**What remains.** Integration is intentionally out of the owner's scope and is recorded as debt: wiring the budget at the graph entry, routing both model tiers and application retries through one dispatch boundary, mapping terminal failures to the C0 status that suppresses an official rating, verifying that the real client's implicit retries are disabled, replacing the static settlement check with a behavioural one, and making the default CI run collect `test/offline`. Until those close, NFR-01 should be described as "implemented and unit-verified", never as "enforced in production".

**Working with agents.** The work followed the course pipeline: a read-only planning session, then tests before implementation, then a build session limited to two files, then a read-only verify session. Two episodes are worth reporting because they show where human judgement was required rather than optional. First, two tests passed against the pre-update draft for the wrong reason (the constructor rejected the new keyword with `TypeError`), which I found only by inspecting why the red baseline had exactly two passes; narrowing the expectation required an explicit decision record. Second, the verify role rejected the race test's expectation that a send through the low-level primitives would be confirmed as delivered, which exposed a genuine mismatch between what C4 promises and what the test assumed. In both cases the agent's pushback was correct and the human's job was to decide which artefact was wrong. A third episode is about tooling rather than reasoning: the planning role was refused read on two documents that the course prompt makes mandatory, because the permission allowlist listed documentation subdirectories instead of the files the workflow names. The earlier workaround of pasting the files into the session was withdrawn, the gap was reported and fixed in the shared baseline, and the plan was re-run so that its evidence comes from the agent's own reads. That episode is also why the verify role's refusal to review files outside its allowlist was accepted as a finding rather than bypassed.
